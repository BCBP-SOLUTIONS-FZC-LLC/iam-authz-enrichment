# CLAUDE.md

This file provides guidance to Claude Code when working with the **AuthZ Enrichment Service** (`iam-authz-enrichment`), a Go microservice in the IAM subsystem.

## What This Repo Is

`iam-authz-enrichment` is a **private Go service** (module: `github.com/BCBP-SOLUTIONS-FZC-LLC/iam-authz-enrichment`, Go 1.26.6+) that implements Envoy's `ext_authz` v3 gRPC contract (`envoy.service.auth.v3.Authorization/Check`) as the platform's Policy Decision Point. It is the **sole inbound interface** — there is no business HTTP API, no database, and it publishes zero events.

**Key responsibilities:**
- Evaluate the §3.1 precedence chain (first-failing-check-wins): subject resolution → read-only gate → base role/department policy → tender-ACL overlay → MFA-freshness gate.
- Cache membership/tenant/tender-ACL context in Valkey with jittered TTLs, serving both the fresh-read and §7 stale-if-error paths from one envelope.
- Consume 5 SQS queues (membership/user/billing/tenant/tender) to evict stale cache entries — idempotent via `ae:processed:{event_id}`, no publishing, poison messages forwarded to each queue's own RedrivePolicy DLQ by platform-events' `WithDLQForwarding` (LLD §16 AE-36 — a malformed body or failed Glue decode on first receipt, a failing message on its 5th delivery after `DeadLetterHandler` logs it; SQS's own redrive is the backstop; a consumer refuses to start on a queue without a RedrivePolicy). Glue-encoded envelopes are decoded by platform-events' `events.GlueDecodeCodec` (strips the 18-byte header; no Glue client needed). `membership-authz-q`'s `MembershipRevoked` (LLD §16 AE-20, Org & Membership's per-user removal cascade signal) gets a wider eviction than its other five event types — also clears every `ae:tender_acl` entry for the user, best-effort, since a whole-membership removal leaves per-grant rows inert instead of firing individual `*Revoked` events.

**Does NOT own:** JWT issuance/validation (Envoy's `jwt_authn` does this — identity is read only from `CheckRequest.Attributes.MetadataContext`, never headers), MFA enrollment, realm/tenant provisioning, any durable schema/database, a policy-authoring UI (policies are compiled-in Go), rate limiting/quota enforcement, active session revocation, durable delegation data (owned by `iam-delegation`, extracted from Org & Membership under ADR-0008 — `active_delegations[]` was dropped from I-8's projection and no longer exists anywhere in this codebase), tender-ACL entries persistence (owned by `iam-tender-acl`, extracted under ADR-0007 Wave 3 Phase 4 — this service still performs the TAC-4 tender-ACL *check*, just against that sibling instead of Org & Membership).

**Source of truth for:** the Allow/Deny decision and its 6 injected headers on every request Envoy proxies. Every service behind this filter is a downstream consumer of this contract — changes to `DenyReason`, header names, or `CheckRequest` field usage ripple everywhere.

**Coverage note:** tests live alongside production code (`internal/.../*_test.go`), not under `test/` — `test/` holds only `fixtures/`, `integration/` and `e2e/` (both build-tag gated), and `load/`. `make test-ci` sets `-coverpkg` to every `internal/...` package (not `cmd/...`, despite `TEST_UNIT_PKGS` running tests there too — `cmd/server`'s `run()` is startup/shutdown wiring that binds real ports and blocks on OS signals, not practically unit-testable to 100% without a larger refactor; this is a deliberate, documented scope choice, not an oversight; `make cover-all` measures it anyway by merging unit coverage with the e2e suite run against a `go build -cover` binary — whole module ~97%, `cmd/server` ~82% — as a report, not a gate, surfaced by the same production-readiness audit that produced §16 AE-33/AE-34 in the LLD). **Tool directive note:** `golangci-lint` is a `tool` entry in `go.mod`, invoked via `go tool golangci-lint`. `go-arch-lint` is installed on demand by `make arch-lint` if missing (not a `go.mod` tool entry, since it's not `go install`-able as a tool directive target the same way).

**No required env vars — with three exceptions:** `internal/config/config.go` gives every field a default (`envOr`) — the binary starts fine with a genuinely empty environment (`APP_ENV` itself resolves via `config.ResolveAppEnv` — `APP_ENV`, then `ENVIRONMENT`, trimmed and lowercased, default `"dev"`, the same precedence the platform libraries use). This is why `.github/scripts/smoke-tests.sh` checks `/healthz` liveness rather than "exits non-zero on missing config" (which is `iam-user-profile`'s pattern, not applicable here). Shared-library env (logging, OTel sampling/propagation, SQS handler/drain/depth tuning) is passed in `deploy/helm/values.yaml` with the same values as iam-org-membership; `SQS_MAX_RECEIVE_COUNT`, `SQS_CONCURRENCY` and `OTEL_SERVICE_NAME` are deliberately not set (overridden in code / redundant), and the Postgres/outbox/SNS vars are deliberately absent (no database, consume-only — `cmd/server` only warns if they are set). `cmd/server/receive_watchdog.go`'s `receiveTrackingClient` must keep forwarding `GetQueueAttributes`, or `SQS_QUEUE_DEPTH_INTERVAL` silently does nothing. The three exceptions, all gated on `APP_ENV` being explicitly set to anything other than `"dev"`: (1) `ORG_MEMBERSHIP_BASE_URL` — or, by the identical check added for the ADR-0007 Wave 3 Phase 4 TAC-4 split, (2) `TENDER_ACL_BASE_URL` — still being its compiled-in dev default, added because that combination used to start clean and then silently fail every non-cache-hit request forever; and (3) any of the five `*_AUTHZ_QUEUE_URL` vars (`MEMBERSHIP_`/`USER_`/`BILLING_`/`TENANT_`/`TENDER_AUTHZ_QUEUE_URL`) left blank — a blank URL starts that consumer idle, which looks healthy (`/readyz` ok) while its cache-eviction/restricted/realm facts never apply. The same block also rejects (regardless of `APP_ENV`) any two of those five vars set to the same URL — undetected, a duplicate would also corrupt `cmd/server/receive_watchdog.go`'s per-URL streak tracking (see that file's own entry below).

### Shared library dependencies

```go
require (
    github.com/BCBP-SOLUTIONS-FZC-LLC/platform-gincommon v1.6.0
    github.com/BCBP-SOLUTIONS-FZC-LLC/platform-events/v2    v2.0.0
    github.com/BCBP-SOLUTIONS-FZC-LLC/platform-pgcommon/v2  v2.0.0
)
```

- `platform-gincommon` — `pkg/logger` (zap + redaction), `pkg/grpccommon` (`ObservabilityUnaryInterceptors`: panic-recovery → request-id → tracing → metrics → logging). **Not** `ProtectedUnaryInterceptors` — Envoy calls this service over mTLS, not as a JWT-bearing client, so there's no bearer auth to require. `grpccommon.RegisterKnownMethods` bounds the `grpc_method` label. `pkg/gincommon` is the **only** OTel/Prometheus entry point, same as iam-org-membership: `InitTracingWithConfig` (same identity as the metrics config), `MetricsHandler` (`/metrics`), `NewCounterVec`/`NewCounter`/`NewHistogramVec` (business metrics), `NewTracer` (usecase spans), `NewSpanTracer` (pgcommon `Config.Tracer`), `InjectTraceContext` (outbound clients). Don't reintroduce local copies (a hand-rolled tracer/propagator, `promauto`, `promhttp`, a local Glue decoder). The one direct OTel import left is `otelhttp` on the outbound transport, which gincommon doesn't wrap (iam-org-membership does the same).
- `platform-events` — `pkg/events` SQS consumer loop (`NewSQSConsumer`, `WithMaxReceiveCount`, `WithConcurrency`, `WithDrainTimeout`, `WithConsumerCodec`), `pkg/config` (`LoadSQS` / `LoadSNS` / `LoadOutbox` / `SNSConfigFromEnv` / `RunnerConfigFromEnv` / `SQSConsumerOptions`), `pkg/outbox` Config mapping. **No publisher or runner**: consume-only (HLD §5.4); `cmd/server` skips `NewSNSPublisher` / `outbox.ApplySchema` / `NewRunner`. Dedup is Envelope.ID via `skipDuplicate` / `ackUnknown`; store is Valkey SET NX (AE-6).
- `platform-pgcommon` — `ConfigFromEnv` / DSN assembly, Zap `domain.Logger` adapter, query tracer via `gincommon.NewSpanTracer`, `pgmetrics.InitWithIdentity` (identity from `gincommon.MetricsConstLabels()`), `NewPool` wrapper. **No live pool**: this service has no schema (HLD §5.4); `cmd/server` loads `PoolConfig` then skips `NewPool` / migrate / outbox. A future schema must open exclusively through `postgres.OpenPool`.

**Not a dependency:** `platform-schemagov` (this service publishes no events, so there's nothing to schema-govern).

### Dependency rules (enforced in CI via `go-arch-lint`)

- `domain` imports nothing outside itself; `domain/policy` imports only `domain`. `config` imports nothing internal at all.
- `usecase` imports only `domain` and `domain/policy` — **never** `config` (TTLs/timeouts arrive as plain constructor parameters, not a config import — see `usecase/ports.go`'s own doc comment).
- `adapter/inbound/*` calls into `usecase` (it's the orchestration layer Envoy's gRPC adapter calls into) — this is the one place the dependency direction differs from `iam-user-profile`'s `core/service`-layer naming; there is no separate `port` package here, `usecase/ports.go` plays that role. One exception: the AsyncAPI viewer (`internal/adapter/inbound/http/asyncapi.go`) reads the embedded spec directly from the `api` package (the compiled-in `api/asyncapi.yaml`, §`api/embed.go`) rather than through `usecase` — the one inbound-adapter dependency besides `usecase`/`domain`/`policy` `.go-arch-lint.yml` allows.
- `adapter/outbound/*` implements `usecase`'s port interfaces; nothing in `domain` or `usecase` imports an adapter.

## Key Files to Know

- **`cmd/server/main.go`** — wiring; `gin.SetMode(gin.ReleaseMode)` outside `APP_ENV=dev` (same convention as `iam-org-membership`/`iam-user-profile`) — found missing entirely by actually running the built binary end-to-end rather than by static analysis; without it, every deployment including production ran Gin in permanent debug mode (per-route registration spam on every startup, Gin's own "switch to release mode" warning in the logs forever). gRPC server gets `reflection.Register(grpcServer)` when `cfg.AppEnv != "prod"` (lets `grpcurl`/`grpcui` discover `Check` without a local `.proto` copy), plus a native `grpc.health.v1.Health` service tied to the same `MarkReady()` signal as HTTP `/healthz`. Listens in plaintext unless `GRPC_TLS_CERT_FILE`/`GRPC_TLS_KEY_FILE` are set (`loadServerTLS`) — see the file's comment on why "Envoy calls over mTLS" is an unverified deployment assumption, not something this server enforces. `grpc.MaxRecvMsgSize`/`MaxSendMsgSize` are set well below the 4MiB default (defense-in-depth, `CheckRequest`/`CheckResponse` are small). The HTTP server (health/readiness only) and the `/metrics` server are two separate `http.Server`s on two separate ports/listeners. Background workers: 5 SQS consumers via `startConsumers`, each idle (no-op) if its queue URL env var is blank, each built with its own `events.WithConcurrency(n)` (`*_AUTHZ_QUEUE_CONCURRENCY` env vars, default 4 — `platform-events`' own default is 1, fully serial per queue), plus `runReceiveErrorWatchdog` (`receive_watchdog.go`) started alongside them as a safety net for a consumer stuck with no successful `ReceiveMessage` — see that file's own entry below. **`fatalErr` (LLD §16 AE-28) — `run()` returns the fatal cause after the graceful shutdown, so the process exits non-zero (SIGTERM still exits 0); `test/e2e/startup_test.go` pins both.**: a single shared, 1-buffered channel fed by every background-failure source in this process — `startConsumers`' goroutines, `runReceiveErrorWatchdog`, and (since `deploy/helm/values.yaml`'s liveness/readiness probes are `httpGet` against the HTTP server only, with no `grpc:` probe on the gRPC port) now also the gRPC/HTTP/metrics server goroutines' own non-graceful `Serve`/`ListenAndServe` exits via a small `reportFatal` helper — closing a gap where a dead gRPC server (100% of Envoy's traffic) could run forever behind a `/healthz` that never noticed. `main()`'s shutdown `select` treats `<-fatalErr` identically to `<-quit`. Shutdown order: gRPC `GracefulStop` → HTTP+metrics `Shutdown` → consumers `Stop()` **concurrently** (a `sync.WaitGroup`, not a sequential loop — bounds worst-case shutdown to one drain window instead of five) → `cancelBackgroundWork` → `cache.Close()`. **LLD §16 AE-33**: `GracefulStop` and the shared HTTP+metrics `Shutdown()` context are each timeout-bounded now (`grpcGracefulStopTimeout`/`httpShutdownTimeout`, 10s each) rather than unbounded/a flat 30s — a wedged Envoy connection or in-flight `Check()` call used to be able to stall every later shutdown step (including the consumer drain) until `terminationGracePeriodSeconds` (60s) forced a SIGKILL that skipped the drain entirely; the rebalanced worst case (10+10+35=55s) fits with a 5s margin. Don't restore a flat 30s HTTP/metrics timeout or an unbounded `GracefulStop` — that reopens exactly this gap.
- **`internal/usecase/check.go`** — `check()` implements the full §3.1 chain, starting with the empty-subject → `DENY_MALFORMED_IDENTITY` check (§8.1, LLD rev 1.31) — `grpc.Server.Check` deliberately does **not** short-circuit it, so that deny is timed and counted in `decisions_total`/`deny_reason_total` like every other; don't move it back into the adapter; **judgment call**: MFA-freshness call failure maps to `DenyMFAStale`, not `DenyServiceUnavailable` (documented inline — a sibling outage on this specific check is treated as "can't confirm freshness" rather than "service down"). `resolveContext`'s outcome switch uses `default:` + `//nolint:exhaustive` rather than an explicit `case OutcomeNormal` — `SiblingReachable: false` is hardcoded at that call site, so `OutcomeNormal` can never actually occur there; an explicit per-value case would compile only with a trailing statement Go's compiler can't prove unreachable, which permanently blocks 100% coverage. Don't "fix" this by re-enumerating the case. `resolveContext`'s two Valkey reads (`GetMembershipContext`/`GetTenantContext`) run concurrently (two goroutines + `sync.WaitGroup`), not sequentially — at the 10ms default `VALKEY_READ_TIMEOUT`, two sequential reads could alone approach the 15ms p99 decision budget (§11.1) on a slow-but-not-erroring Valkey. Verified race-clean (`-race -count=5`). **The singleflight-coalesced I-8 call runs on `context.WithoutCancel(ctx)`** (LLD rev 1.32): under the first caller's context, Envoy cancelling that one request failed every request waiting on the same key (`TestCheck_Singleflight_FirstCallerCancelled_OthersUnaffected`). Don't pass the request `ctx` back into `sf.Do`. Sibling timeouts must never be set below the siblings' own p99 targets (AE-37: I-8 40ms, TAC-4 30ms); `GRPC_REQUEST_TIMEOUT` caps each `Check` server-side. **Two Valkey clients:** the request path's `cache` (10ms `VALKEY_*_TIMEOUT`) and `eventCache` (`cache.WithTimeouts(VALKEY_EVENT_TIMEOUT)`, 500ms) for everything the SQS consumers write — the invalidator, the `ae:processed` ledger, and (via `cmd/server/factstore.go`) `SetRealm`/`SetRestricted` on the shared `RealmMap`/`RestrictedTenderSet`, whose reads stay on `cache`. Don't bind consumer writes to the 10ms client: one slow round trip then costs a 30s visibility-timeout retry. The e2e harness pins `SQS_WAIT_SECONDS=1` / `SQS_VISIBILITY_TIMEOUT=5s` for run-to-run isolation — don't remove them.
- **`internal/usecase/failure.go`** — `DecideDependencyOutcome()` is the §7 table as a pure function, deliberately its own package-level function (not scattered in adapter code) so the test suite can exercise every row directly. The tender-ACL overlay's fail-closed rule is independent of this table — checked separately in `check.go`.
- **`internal/adapter/outbound/valkey/cache.go`** — `mfa_freshness_seconds` is **never** written here — hard invariant, has a dedicated regression test. Any change that folds MFA freshness into the `ae:ctx` envelope is a security regression, not a refactor.
- **`internal/usecase/invalidate.go`** — `HandleUserDeleted` and `HandleMembershipRevoked` share the same best-effort-tender-ACL-eviction shape: `EvictTenderACLForUser` failure logs a warning but never fails the event, since a partial scan degrades to "stale until its 15s TTL expires", not a correctness failure requiring retry. `HandleMembershipRevoked` (LLD §16 AE-20) exists because a whole-membership removal soft-deletes the `tenant_memberships` row and leaves per-grant rows inert rather than firing individual `*Revoked` events — it's the only `membership-authz-q` event type that needs the wider eviction the other five don't.
- **`internal/adapter/inbound/consumer/idempotency.go`** — `processedHandler()` marks-then-handles via `skipDuplicate` (`MarkProcessed`, SET NX — the atomic check *is* the duplicate check, no separate `IsProcessed` step exists or is needed); on handler failure it calls `Cache.EvictProcessed()` to undo the mark, or a failed message would be falsely treated as already-processed on redelivery and silently skipped instead of retried (this was a real bug, caught by `TestSQS_DLQ_MessageMovesAfterMaxReceiveCount` timing out — see `TestDedupingHandler_RetriesAfterHandlerFailure`). `dedup.go`'s `ackUnknown` is the sibling forward-compat path for an unwired event type (log + ack; the wrapper already claimed the ID). **LLD §16 AE-34**: a `defer`/`recover()` around the handler call does the identical `EvictProcessed` cleanup for a **panic**, not just a returned error, then re-panics so `platform-events`' own top-level recovery still runs unchanged — a panic used to bypass the eviction path entirely, which for most queues only cost a stale cache entry until its TTL but for `tender-authz-q` would have permanently disabled the tender-ACL overlay for that tender (`ae:restricted` has no TTL, §8.5.1).
- **`internal/config/config.go`** — every `envInt`-backed field that can silently misbehave on a zero/negative value goes through `envPositiveInt` instead (`GRPC_MAX_CONCURRENT_STREAMS`, both gRPC message-size limits, all five `*_AUTHZ_QUEUE_CONCURRENCY` vars) — a gRPC server accepting zero concurrent streams, a consumer built with negative concurrency, or a message-size cap that admits nothing should crash-loop the pod at startup, not surface as a confusing runtime symptom (LLD §16 AE-33/AE-34's audit, same fail-fast philosophy as the existing duplicate-queue-URL/dev-default checks below). `GRPC_MAX_CONCURRENT_STREAMS` additionally gets an explicit `math.MaxUint32` range check before its `uint32(streams)` narrowing conversion — an oversized value would otherwise wrap silently instead of erroring. Same philosophy: `GRPC_REQUEST_TIMEOUT` and `VALKEY_EVENT_TIMEOUT` must be positive, and a `VALKEY_URL` containing `://` must pass `redis.ParseURL` (LLD rev 1.32) — the cache adapter otherwise falls back to treating it as a plain `host:port`, so a typo'd `rediss://` URL starts with TLS silently off and, since `/readyz` ignores Valkey, fails every request closed. `ResolveAppEnv()` (`APP_ENV` → `ENVIRONMENT` → `dev`, trimmed/lowercased) is the single environment source for `Load()` and `cmd/server` — don't read `APP_ENV` directly anywhere.
- **`cmd/server/receive_watchdog.go`** — verified against the vendored `platform-events` source that its SQS consumer's `Start()` never returns an error for a persistently failing `ReceiveMessage` loop (revoked IAM permissions, a deleted queue) — it retries forever internally, so the existing `fatalErr` restart channel never fires for that failure mode on its own. This file closes the gap: `startConsumers` hands each consumer its own `receiveTrackingClient` (a decorator over the shared `*sqs.Client`) that counts that consumer's `ReceiveMessage` errors and successes, and the watchdog pushes to `fatalErr` after `staleAfter` (6) consecutive 30s polls with new errors and no successful receive. It deliberately does not read a metric back from the Gatherer: platform-events' former per-queue SQS receive-error counter was removed, and its successor `platform_dependency_request_seconds_count{dependency="sqs",operation="receive_message",outcome="error"}` has no `queue` label and is fail-soft (it can be disabled on a registration conflict). Each consumer has its own tracker, so two friendly names sharing a URL cannot reset each other's streak; `config.go`'s duplicate-queue-URL fail-fast check (above) still rejects that misconfiguration at startup.
- **`internal/adapter/inbound/grpc/claims.go`** — `decodeClaims()` reads only `req.Attributes.MetadataContext[cfg.Namespace].Fields[cfg.PayloadKey]` — never `req.Attributes.Request.Http.Headers`. A code path that falls back to headers is an identity-spoofing vulnerability, not a convenience fix.
- **`internal/adapter/inbound/grpc/requestfacts.go`** — `tenderIDFromPath()` parses `tender_id` out of `req.Attributes.Request.Http.Path`'s `/tenders/{id}` segment; it is deliberately **not** one of the `ContextExtensions` keys (§16 AE-22 in the LLD). `ExtAuthzPerRoute.check_settings.context_extensions` is a static `map<string,string>` an Envoy route author writes once per route at config time — it has no per-request templating, so it cannot carry a genuine per-resource ID the way it can a route-invariant fact like `policy_action`. Every tender-scoped route (GET/POST/PUT/PATCH/DELETE alike) must keep the tender ID in the URL path — a body-only ID silently disables the tender-ACL overlay for that route instead of erroring.
- **`internal/adapter/inbound/http/router.go`** / **`asyncapi.go`** — the AsyncAPI HTML viewer (`GET /asyncapi`) and raw-spec endpoint (`GET /asyncapi.yaml`), gated by `DocsConfig` (`Environment`/`Enabled`/`AuthToken`): always mounted outside `APP_ENV=prod` (the only production spelling a running process can see — gincommon rejects `production` at startup), opt-in via `DOCS_ENABLED` in prod, optionally bearer-token-gated via `DOCS_AUTH_TOKEN`. Ported verbatim from `iam-tender-acl`'s identical renderer — entirely YAML-driven off the embedded `api/asyncapi.yaml`, no service-specific logic. No Swagger half, since this service has no business HTTP API to document one for. `asyncapi.go`'s description/summary truncation **must** go through `truncateRunes` (rune-boundary-safe), never a bare `s[:N]` slice — this was a real bug: `api/asyncapi.yaml`'s `info.description` uses multi-byte box-drawing characters (`─`, U+2500) to draw its producer table, a byte-level `s[:800]` cut landed mid-character, and the `/asyncapi` page rendered `�` (U+FFFD) instead of the description. Caught by `TestAsyncAPIHandler_RealSpec_NeverEmitsReplacementCharacter`, which renders the real embedded spec and asserts no `�` appears anywhere in the output.
- **`internal/adapter/outbound/metrics/recorder.go`** — `New(reg)` builds every `iam_authz_enrichment_*` metric through gincommon's Tier 3 constructors, which validate names/labels against the Platform Observability Registry and **require gincommon's metrics identity to exist first** (`cmd/server` calls `ObservabilityMiddlewares` before `metrics.New`; the test file's `TestMain` does the same). It returns an error naming every failing metric instead of panicking. Tests pass an isolated `prometheus.NewRegistry()`; only `TestNew_NilRegistererUsesMetricsRegisterer` touches the real registerer. `deny_reason_total{reason}` emits the `DenyReason` **lowercased** (`deny_service_unavailable`), because the registry's `reason` vocabulary is snake_case. `TestNew_AppliesGincommonConstLabels` emits every series and runs `obsregistry.Validate`, which is what caught the upper-case value. Keep it emitting every metric, or a new label violation goes unnoticed the same way.
- **`test/fixtures/cache.go`** — `FakeCache` has a `*Err` field per operation (`SetCtxErr`, `GetTenderACLErr`, `EvictProcessedErr`, …) for error-injection tests; it does not use gomock/mockery, matching `iam-user-profile`'s convention.
- **`test/e2e/main_test.go`** — `TestMain` builds the fake Org & Membership/Tender ACL server, starts the real compiled binary (`E2E_BINARY_PATH`, default `../../bin/iam-authz-enrichment` — `make build` first) as a subprocess with SIGTERM-then-Kill teardown (exercising the real §16 AE-33 graceful-shutdown path), and dials it over a real gRPC connection before running any test. **`runID`/`id()`**: every tenant/tender name a test constructs must go through `id()`, which suffixes a per-process UUID — this suite runs against a real, persistent Valkey (not reset between invocations), and `ae:restricted` has no TTL by design (§8.5.1), so an unscoped name lets one run's residual restriction state corrupt a later run's "not yet restricted" assertion. This bit a first draft of `TestTenderACLOverlay_FullFlow` before the fix. Also: `fakeorg.go`'s `tenderACLFixture.ExpiresAt` must stay `time.Time`, never `string` — the real client decodes TAC-4's response directly into `domain.TenderACL{ExpiresAt time.Time}`, and an empty-string JSON value fails that unmarshal, which is indistinguishable from every other `GetTenderACL` error and fails closed to `DENY_TENDER_ACL_INSUFFICIENT` — a mock bug that looks exactly like a real denial (caught by this suite itself before landing). **Never name a file in this package `mockorg*`** (or add one elsewhere in the repo) — `.gitignore`'s `mockorg*` rule (for README's own throwaway local `mockorg/` walkthrough directory) glob-matches that basename anywhere in the tree, not just at the repo root. A file named `mockorg.go` here was silently excluded from every `git add`, built and passed locally (`go test` reads the working directory regardless of git tracking state), and only broke in CI's fresh checkout with `undefined: mockOrg` — fixed by renaming to `fakeorg.go`/`fakeOrg`, which also matches this codebase's existing test-double naming (`test/fixtures`' `FakeCache`) better than "mock" did anyway.
